# M5 Apps and v1.0

Ends with: `v1.0.0` is out. `docker pull oxisoft/oxipoker:1.0.0` runs on amd64 and arm64, the desktop apps for Windows, macOS and Linux are on GitHub Releases (macOS signed and notarised), the Android app installs and updates from fdroid.oxisoft.io, and someone who has never seen the project sets up a server from the install guide alone.

Versions checked online on 2026-11-19: Go 1.27.4, Flutter 3.50.0, LiveKit server v1.13.11, livekit_client 2.14.0, flutter_background 1.3.1.

## Rules

- One tag `vX.Y.Z` builds everything: the Docker image, the Android APK and the three desktop builds. Nothing is built by hand for a release.
- Release artefacts are built on GitHub-hosted runners from the public source, so anyone can see how a binary was made.
- The Android APK is signed with Oxi Poker's own key (not Play App Signing); its certificate fingerprint is published in the README so F-Droid users can check it.
- macOS builds are signed with a Developer ID certificate and notarised; Windows builds are unsigned and the install guide shows the SmartScreen step; Linux ships as a tarball.
- A client of version 1.x works with every 1.x server; the app shows the server's version and says plainly when the server is too old for it.
- The security review is written down and published with the release; every finding is fixed or explained.

## Tasks

### Release builds
- [ ] Android release APK in the release workflow, signed with the upload key from repository secrets, signer fingerprint checked in the job, attached to the GitHub release
- [ ] Desktop builds in the release workflow: Linux x64 tarball, Windows x64 zip, macOS universal dmg; attached to the GitHub release with SHA-256 sums
- [ ] macOS signing and notarisation: Developer ID Application certificate and App Store Connect API key from repository secrets, hardened runtime, `notarytool` submit and staple; the job skips signing with a warning when the secrets are missing
- [ ] Version: the build number and git tag go into the server binary and every app; `/health` reports it; the app's About screen shows app and server version and warns when the server is older than the app supports

### Android on F-Droid
- [ ] Oxi Poker in fdroid.oxisoft.io: metadata (summary, description, screenshots, licence, source link, anti-features none), the release APK added on every release by the release workflow, the repo index re-signed and deployed
- [ ] README and install guide: how to add the repo, the APK signer fingerprint

### Install and operate
- [ ] Install guide `docs/INSTALL.md`: minimal option in five commands, full option with voice and video, HTTPS with Caddy or nginx, first admin, invitations
- [ ] Operations in the guide: upgrade, backup and restore of the data volume (SQLite online backup), logs, moving to a new box
- [ ] Connection check in the admin console (full option): signalling reachable, TURN TLS port answers, token round trip, with a plain explanation for each failure
- [ ] Clean-box test: a fresh VM follows only the guide, minimal and full option, every step that needed knowledge not in the guide is added to it

### Security review
- [ ] Review written in `docs/SECURITY-REVIEW.md`: authentication (passwords, passkeys, TOTP, sessions, rate limits), invitations, WebSocket origin and limits, per-seat view filtering, history privacy, uploads, media tokens, admin actions, HTTP headers and CSP of the web app, container (non-root, read-only filesystem)
- [ ] Automated checks in CI: `govulncheck`, a test that no view or history response for one user ever carries another user's unshown hole cards across a full table of played hands, dependency review on pull requests
- [ ] Fixes for every finding, each with a test

### v1.0.0
- [ ] Dependencies upgraded to the newest releases on the day (Go modules, Flutter packages, LiveKit), CI green
- [ ] `CHANGELOG.md` from M0 to M5, README updated (screenshots, download links, F-Droid, install guide)
- [ ] Tag `v1.0.0`: image on Docker Hub (amd64 + arm64), GitHub release with APK and desktop builds, F-Droid updated; hand-written release notes
- [ ] Test server on `1.0.0`; Pilot tickets per task group under the M5 epic; acceptance steps posted in the room

## Acceptance

1. CI green on main and on the `v1.0.0` tag; `docker pull oxisoft/oxipoker:1.0.0` works on amd64 and arm64.
2. The GitHub release has the APK, the three desktop builds, checksums and hand-written notes.
3. On a Mac the dmg opens without a Gatekeeper warning (`spctl -a -vv` says notarised); the Windows and Linux builds start and sign in to poker.oxisoft.net.
4. The F-Droid client with fdroid.oxisoft.io added installs Oxi Poker, and the next release arrives as an update.
5. A fresh VM gets a working server, minimal and full option, from `docs/INSTALL.md` alone.
6. `docs/SECURITY-REVIEW.md` is published, every finding fixed or explained; `govulncheck` is clean.
