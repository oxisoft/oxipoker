# M2 Game: cash tables

Ends with: on the test server, friends play a real No-Limit Hold'em cash game in the browser and on Android, with spectators and text chat; afterwards each player sees the hand history and personal stats.

Versions checked online on 2026-11-18: Go 1.27.4, Flutter 3.50.0, coder/websocket v1.8.15, golang.org/x/crypto v0.59.0, web_socket_channel 3.0.3, flutter_riverpod 3.5.0, go_router 18.1.4.

## Rules

- The server is the only game authority. The app holds no game logic: it draws what the server sends and sends intents.
- Each WebSocket message is built per viewer: another player's hole cards never leave the server until shown at showdown. Spectators see no hole cards.
- Shuffle from `crypto/rand` only. Every hand is replayable from its stored history.
- Chips are never created or lost: the sum of stacks and pots is constant inside a hand (property tested).
- The web client makes no third-party requests (fonts bundled).

## Tasks

### Web assets
- [x] Bundle the UI font and a font with the card suit glyphs; the web build loads no font from fonts.gstatic.com (checked in CI by grepping the build and in a browser network log)

### Engine
- [x] Cards, deck, shuffle from crypto/rand (injectable source for tests)
- [x] Hand evaluator (7 cards, best 5), checked against all 2,598,960 five-card hands (category counts, 7,462 distinct values) and against an independent slow evaluator in tests
- [x] Hand state machine: blinds (incl. heads-up order and dead button), betting rounds, min-raise rules, all-in for less does not reopen betting, street dealing, showdown order
- [x] Side pots and split pots with odd chips (odd chip to the first seat left of the button)
- [x] Rules behind an interface (betting structure, hole-card count) so Pot-Limit Omaha can plug in later
- [x] Property tests (chip conservation, legal actions only) and a fuzz test on random action sequences; CI runs a fuzz smoke test

### Tables
- [x] Table actor: one goroutine per table owns the state; seats, buy-in with the table's starting stack, sit out, come back, leave
- [x] Turn timer: on timeout check or fold; two missed turns sit the player out; disconnect keeps the seat
- [ ] Table settings from the host: name, seats 2-9, blinds, starting stack, turn time, spectators on/off; the admin setting "table creation admin-only" is enforced
- [ ] Host and admin can close a table; empty tables close after a while

### Realtime
- [ ] WebSocket endpoint (coder/websocket) with session auth and Origin check; one connection per tab
- [ ] Per-viewer views (seat, spectator) built on the server; tests prove no hidden card is ever serialised for another viewer
- [ ] Intents: sit, buy in, fold, check, call, bet/raise N, sit out, leave, chat; invalid intents get an error, never a state change
- [ ] Reconnect resumes the current view at once (mobile browsers that slept)

### Lobby and chat
- [ ] Lobby API + live updates: tables with seats taken, blinds, players; create table
- [ ] Text chat per table for players and spectators over the same WebSocket, rate limited, not stored after the table closes

### History and stats
- [ ] Hand history stored per hand (actions, board, cards shown at the table only); list own hands, replay one
- [ ] Personal stats: hands played, hands won, biggest pot

### App
- [ ] Lobby screen (list, create table dialog)
- [ ] Classic table UI: green felt, wood rail, seats with avatar, stack, bet, cards; board, pots, dealer button, turn timer
- [ ] Action bar: fold, check/call, bet/raise with slider and presets; only legal actions enabled
- [ ] Spectator mode, chat panel, hand history list and replay, stats on the account screen

### Quality
- [ ] Go tests for engine, table, realtime and every new endpoint; `docs/API.md` covers the WebSocket protocol
- [ ] Flutter widget tests for lobby, table and action bar
- [ ] Load check: 9-seat table with 20 spectators on the test server stays responsive
