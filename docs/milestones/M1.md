# M1 Accounts and admin

Ends with: on the test server, Alex signs in with a passkey, creates an invitation link, and a second user registers through it.

Versions checked online on 2026-11-18: Go 1.27.4, Flutter 3.50.0, go-webauthn/webauthn v0.18.2, ncruces/go-sqlite3 v0.36.0, chi v5.5.0, golang.org/x/crypto (argon2id) latest, pquerna/otp (TOTP) latest, flutter_riverpod 3.5.0, go_router 18.1.4, passkeys 2.24.2.

## Rules

- No open registration, ever: accounts come from an admin or an invitation link.
- Secrets are never logged. Passwords: argon2id. Session tokens: 32 random bytes, only their SHA-256 is stored.
- Every state-changing request checks the Origin header against `PUBLIC_URL` (CSRF), plus SameSite=Lax cookies.
- The server makes no outbound calls.

## Tasks

### Storage
- [x] SQLite store in `DATA_DIR` (WAL, foreign keys, busy timeout), embedded SQL migrations with a version table
- [x] Server secret material generated on first start and kept in the data volume (never in env unless set)
- [x] Audit log table for admin and security events (who, what, when, from which IP)

### Accounts
- [x] Users: id, username (unique, case-insensitive, 3-32 chars), display name, password hash, admin flag, avatar, created, disabled
- [x] First admin from `ADMIN_USERNAME` / `ADMIN_PASSWORD` on first start; ignored (with a log line) once any admin exists
- [x] Sessions: HttpOnly Secure cookie for the web app, `Authorization: Bearer` for native apps; list and revoke own sessions; expiry with sliding renewal
- [x] Password sign-in with per-IP and per-account rate limits; same answer for unknown user and wrong password
- [x] Passkeys (WebAuthn): register, sign in (discoverable credentials), list, rename, remove; RP ID from the `PUBLIC_URL` host
- [x] TOTP 2FA: enroll with QR, confirm with a code, disable, 10 one-time recovery codes
- [x] Own account: change display name, change password, delete own account (last admin cannot)
- [ ] Avatars: upload, decode, crop square, re-encode to WebP or PNG at 256 px, size cap, no SVG, metadata stripped

### Invitations
- [ ] Admin creates a link: expiry, number of uses, optional note; list, revoke; see who joined through it
- [ ] Sign-up through a link: username + password, or username + passkey; link checked again at submit

### Admin console
- [ ] Users: list, search, create, disable, delete, reset password (one-time temporary password), reset 2FA, make or remove admin (last admin protected)
- [ ] Server settings: table creation open or admin-only, maximum upload size
- [ ] Audit log view

### App
- [ ] Server address screen for native apps (web app uses its own origin); invitation links carry the server address
- [ ] Sign-in (password, passkey, TOTP step), sign-up from an invitation, account screen, admin console screens
- [ ] State with flutter_riverpod, routes with go_router, strings through gen-l10n (English ARB only for now)
- [ ] Passkeys on web through the browser WebAuthn API; Android and desktop through the passkeys plugin

### Quality
- [ ] Go unit tests for every module and HTTP integration tests for every endpoint (including the negative cases: expired invite, reused invite, last admin, wrong origin, rate limit)
- [ ] Flutter widget tests for the sign-in and admin screens
- [ ] `docs/API.md` lists every endpoint

## Acceptance

1. Fresh `docker compose up` with `ADMIN_USERNAME`/`ADMIN_PASSWORD` creates the admin; restart with other values changes nothing.
2. On poker.oxisoft.net: the admin creates an invitation; Alex registers through it with a passkey; the admin makes Alex an admin; Alex signs in with the passkey on a second device type.
3. A used single-use link and an expired link both refuse sign-up.
4. CI green, edge image deployed on the test server.
