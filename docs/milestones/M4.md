# M4 Voice and video

Ends with: on the test server a table runs with voice and video on web, Android and desktop at the same time, one player joins from behind a strict router through TURN, and the host mutes and removes someone from the call.

Versions checked online on 2026-11-19: Go 1.27.4, Flutter 3.50.0, LiveKit server v1.13.11, LiveKit Go server SDK v2.20.0, livekit_client (Flutter) 2.13.2 (2.14.0 when the app part started, same day).

## Rules

- The full option is the minimal option plus the LiveKit container from the same Compose file. Without LiveKit settings the server runs exactly as in M3 and the app shows no media controls.
- Oxi Poker writes no media code: LiveKit carries audio and video, the Oxi Poker server only decides who may join which call and with which rights, and says so in short-lived tokens.
- One call per table. Only signed-in users who are seated or watching that table get a token; leaving the table, being removed or the table closing ends their call.
- Media is never recorded or stored by Oxi Poker.
- Everyone controls their own camera and microphone. Joining a table never turns on the camera or the microphone by itself.
- Blocking someone also hides their video and silences their audio for you, in the app, without telling them.
- The game never waits for media: a call that fails to connect leaves the table fully playable.

## Tasks

### Server
- [x] Settings: LIVEKIT_URL, LIVEKIT_API_KEY, LIVEKIT_API_SECRET; media is on when all three are set (a partial set stops the start); `GET /health` tells the app whether media is available
- [x] Token endpoint for a table: room = table id, identity = user id, name = display name, 10 minute lifetime, publish and subscribe for players and spectators, refreshed by the app before expiry; refused for users who are not at the table or were removed
- [x] Moderation through the LiveKit server API: host or admin mutes a participant's microphone or camera and removes someone from the call; a removed user gets no new token while the table is open; the call room is deleted when the table closes
- [x] Tests: token claims and refusals, moderation calls against a fake LiveKit API, minimal option unchanged

### App
- [x] Join the table's call with livekit_client; microphone and camera off on join; own controls for microphone, camera, speaker, camera switch on mobile
- [x] Video tiles at the seats (players) and a spectator strip; avatar when the camera is off; speaking indicator
- [x] Host and admin menu on a participant: mute microphone, stop camera, remove from the call; blocked users hidden and silenced locally
- [x] Permissions on Android (camera, microphone, foreground service for calls in the background), macOS entitlements, web over HTTPS only; clear message when a permission is refused
- [x] Widget tests with a fake room: controls, tiles, moderation menu, media hidden when the server has no media

### Deployment
- [ ] Compose full profile: LiveKit ports configurable (signalling, RTC TCP, RTC UDP, TURN), TURN over TLS for strict routers, settings documented in `.env.example` and the README
- [ ] Reverse proxy example for the LiveKit signalling path (WebSocket upgrade) and the TURN TLS certificate
- [ ] Test server switched to the full option (its own ports, next to the box's other services), firewall rules for the media ports

## Acceptance

1. CI green: token, moderation and widget tests pass; the edge image runs on the test server with the full option.
2. Three players at one table on poker.oxisoft.net, one each on web, Android and desktop, see and hear each other.
3. One of them is behind a network that blocks UDP and still joins through TURN over TLS.
4. The host mutes one player and removes a spectator from the call; the removed spectator cannot rejoin the call until the table is reopened.
5. A player blocks another and no longer sees or hears them.
6. The minimal option (no LiveKit settings) still runs the M3 game unchanged.
