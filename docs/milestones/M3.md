# M3 Sit-and-go and finish

Ends with: on the test server, friends play a full sit-and-go to one winner, once in the classic theme and once in the cyberpunk theme; a server restart in the middle of the game resumes the table; the app speaks about ten languages.

Versions checked online on 2026-11-18: Go 1.27.4, Flutter 3.50.0, Weblate 2026.11.2 (Hosted Weblate, libre plan for open source).

## Rules

- Everything from M2 still holds: the server is the only game authority, each client gets only its seat's view.
- A sit-and-go creates no chips: every player starts with the same stack, nobody rebuys, the game ends when one player holds every chip.
- The blind clock runs on the server. Clients show the level and the time left, they never decide when blinds rise.
- Uploaded images (card backs) are re-encoded on the server like avatars: metadata stripped, size capped before decoding.
- Report and block never reveal to the reported user who reported them.

## Tasks

### Sit-and-go
- [x] Table kind `sng` next to `cash`: seats 2-9, starting stack, blind structure (built-in presets turbo, regular, slow; level length in minutes), late join off, no rebuy
- [x] Registration: players take seats until the host starts or every seat is full; the first hand starts with a random button
- [x] Blind clock on the server: levels rise between hands when the level time is over; the view carries level, blinds, next blinds and time left
- [x] Elimination order and places; the last player wins; results stored with the hand history; stats gain sit-and-go games, wins and best place
- [x] Sitting out in a sit-and-go keeps posting blinds and folding (standard rule), so the game always ends
- [x] Lobby and table UI: kind picker in the create dialog, registration list with a start button for the host, blind level bar, final standings screen

### Server restart resume
- [x] Table state (settings, seats, stacks, button, blind level and its time left) written to SQLite after every hand and on shutdown
- [x] On start the server restores open tables; a hand cut off by a crash is voided and every stack goes back to its value at the start of that hand
- [x] Graceful shutdown (SIGTERM): finish no new hand, store the tables, tell clients the server restarts; apps reconnect and re-watch on their own
- [x] Test: play, kill the server mid-hand, start it again, check stacks equal the hand-start stacks and play continues

### Themes and card backs
- [ ] Cyberpunk theme in the OxiSoft palette (dark base, electric blue, electric red, orange accents, no cyan) as a per-user switch on the account screen, stored on the server; classic stays the default
- [ ] Built-in card backs (at least four designs, two per theme), admin picks the server default, each user may pick their own
- [ ] Admin uploads card backs (PNG, JPEG or WebP; re-encoded to a 5:7 PNG; size cap from the avatar setting); admin can delete uploads that are not the default

### Report and block
- [ ] Block a user: their chat lines are hidden for you (and their video in M4); the block list on the account screen
- [ ] Report a user with a reason (chat, behaviour, other) and an optional note; reports go to the admin console with the last chat lines of that table as context
- [ ] Host moderation for chat: mute a player or spectator at the table, remove a spectator

### Languages
- [ ] Every user-facing string in ARB files; the server sends error codes, the app translates them
- [ ] Machine-translated ARB files for de, es, fr, it, pt-BR, pl, ru, uk, tr, ja, zh-Hans; language picker on the account screen, default from the device
- [ ] Weblate project for the app strings (Hosted Weblate libre plan), linked from the README for community fixes

## Acceptance

1. CI green: sit-and-go and restart tests pass, edge image deployed on the test server.
2. On poker.oxisoft.net three or more players play a sit-and-go to one winner in the classic theme; the standings and the stats show the result.
3. A second sit-and-go is played with at least one player on the cyberpunk theme and a custom card back.
4. During a game the test server container is restarted; the table comes back with the right stacks and play continues.
5. A player blocks and reports another; the admin sees the report.
6. The app is switched to two other languages and every screen of a hand is translated.
